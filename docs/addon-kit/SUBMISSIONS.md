# Curated submissions — first version

This is a reviewed developer preview, not an upload marketplace. The SDK and examples are open source; distribution through Wise Routine is a separate approval process. Authors retain ownership. There is no submission fee, addon payout, commission or paid-addon entitlement in v1; these are not promises about future marketplace terms.

## Author checklist

1. Build without the private repository using this kit. Change reserved IDs in forks.
2. Publish source at an immutable full GitHub commit; include dependency lockfile, tests and license text. Source and all bundled assets/dependencies must permit commercial redistribution. Initial accepted licenses: MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC. Keep attribution/NOTICE obligations; do not assume a permissive top-level license covers incompatible dependencies.
3. Copy the starter's `submission.example.json` to `submission.json`. Supply author, license, source repository/commit, HTTPS support URL, privacy/data-retention explanation. Include screenshots or a short recording and permission rationale in the PR.
4. Run `wr-addon validate .`, test denial/disconnection and all contributed roles, then `wr-addon package .`. The artifact is unapproved and unsigned.
5. Open a PR in the **public addon registry/kit repository designated by the operator**, not the private application repository. Add submission metadata linking the exact source commit and artifact digest. Do not attach credentials or executables disguised as review documents.

## Reviewer checklist

- Verify control of the namespace/repository and identity of the submitting maintainer. Repository ownership cannot be inferred from a self-written author string.
- Review source, lockfile/dependency provenance, build commands, generated bytes, licenses/assets/notices, permissions and data-retention/support commitments. Reject misleading descriptions or Pro/subscription claims.
- Build in an isolated disposable runner with no release/deploy/npm credentials. Pin the source commit; record toolchain versions, artifact digest, review decision and reviewer. Do not run contributor scripts in trusted promotion.
- Test widget, session type selection, Quick Add, missing/denied permissions, empty data, full storage and RPC abuse. Confirm no arbitrary source loading or exfiltration paths. No third-party network/secret/background integrations in the initial cohort.
- Use a **separate staging API and app build** with test approval keys, databases and synthetic accounts. Add the reviewed descriptor to staging's catalog and upload the matching bundle; build the client with the same staging public keys. Backend writes must traverse real addon authorization. Do not weaken production gates for sideloading.
- Test clean native install, explicitly approved update, permission narrowing, rollback, revocation while running, offline lease expiry, account switch, interrupted installation and safe mode. Include Free and Pro accounts.

## Promotion and operation

After human approval, a trusted operator signs **only the verified data**, using `scripts/approve-addon.mjs` in the private integration repository. It never runs source from an artifact. The P-256 private key remains in the trusted stage; public keys are committed to app/server trust configuration. Upload exact bundle bytes under `<sha256>.js` to the controlled bucket, then add the signed descriptor and current ID/version pointer to the catalog. The app downloads through its API origin; arbitrary CDNs are not part of v1.

Catalog changes, new trust keys and promotion tools require owner review and protected branches. Never overwrite an existing ID/version or hash object. Keep approved old descriptors/artifacts and bundled manifest history. Rollback changes the offered current pointer; already installed versions change only by explicit installation/approval. Security revocation names an entire ID or `id@version`, is enforced independently of the current pointer, and takes precedence over continued operation.

Approval is revocable and is not a guarantee of safety or a support SLA from Wise Routine for third-party code. The operator may decline or withdraw distribution. Authors may stop future submissions, but cannot revoke rights already granted under an irrevocable open-source license. Confirm privacy, redistribution, trademark and store/legal requirements with counsel before opening the public program.
